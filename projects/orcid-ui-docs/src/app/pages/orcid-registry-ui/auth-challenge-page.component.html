This component manages the UI switching and validation logic between the password field, 2FA code, and recovery code inputs. You must pass a parent [formGroup] into it so it can attach its controls.

It can be rendered as a MatDialog, injected dynamically via CdkPortalOutlet, or used as a standard HTML tag. Note: When using MatDialog, pass configuration properties inside the data object. Otherwise, bind them as standard @Input() properties.

1. Form Configuration

Initialize the controls in your parent component. Note that Validators.required for the 2FA fields is managed automatically by the component based on the fields currently being shown. 

this.form = this.fb.group({
  // ... other controls like 'id'
  password: [null, Validators.required],
  twoFactorCode: [null, [Validators.minLength(6), Validators.maxLength(6)]],
  twoFactorRecoveryCode: [null, [Validators.minLength(10), Validators.maxLength(10)]],
  // only needed when you pass a recoveryPhone
  twoFactorRecoveryPhoneCode: [null, [Validators.minLength(6), Validators.maxLength(6)]],
});

2A. Usage via MatDialog

openAuthChallenge() {
  // 1. Open the dialog
  const dialogRef = this._matDialog.open<AuthChallengeComponent>(
    AuthChallengeComponent,
    {
      data: {
        parentForm: this.form,
        actionDescription: 'to unlink the alternate sign in account',
        boldText: 'Google',
        trailingText: 'to continue.',
        showTwoFactorField: this.twoFactorState, // true or false
      } as AuthChallengeFormData,
    }
  );

  // 2. Listen for the verify button click inside the dialog
  dialogRef.componentInstance.submitAttempt
    .pipe(
      takeUntil(dialogRef.afterClosed()),
      switchMap(() => this.myService.delete(this.form.value).pipe(first()))
    )
    .subscribe({
      next: (response: any) => {
        if (response.success) {
          dialogRef.close(true);
        } else {
          dialogRef.componentInstance.processBackendResponse(response);
        }
      },
    });

  // 3. Listen for cancel or close
  dialogRef.afterClosed().subscribe((success) => {
    this.form.reset();
  });
}

2B. Usage via CdkPortalOutlet

First, add the outlet container to your HTML and query it in your TS file. 

<!-- In your parent HTML -->
<ng-container #authChallengeOutlet cdkPortalOutlet></ng-container>
// In your parent TS file
@ViewChild('authChallengeOutlet', { static: false, read: CdkPortalOutlet }) outlet!: CdkPortalOutlet;

showAuthenticationChallenge(): void {
  const portal = new ComponentPortal<AuthChallengeComponent>(AuthChallengeComponent);
  const componentRef = this.outlet.attachComponentPortal(portal);

  // Bind inputs directly to the instance
  componentRef.instance.parentForm = this.form;
  componentRef.instance.actionDescription = 'to complete your password reset';
  componentRef.instance.showPasswordField = false;

  componentRef.instance.submitAttempt.subscribe(() => {
    // Handle submission and call componentRef.instance.processBackendResponse(res) on error.
    // On success, navigate away.
    this.router.navigate(['/success']);
  });

  componentRef.instance.cancelAttempt.subscribe(() => {
    this.form.reset();
    // TIP: If staying on the same page, use this.outlet.detach() to close the view.
    // If routing away, DO NOT detach it manually to avoid a UI flash. Angular will clean it up!
    this.router.navigate(['/signin']); 
  });
}

4. Backend Implementation

The backend validation consists of verifying the password and the 2FA status. If both pass, set success to true. 

ProfileEntity profile = profileEntityCacheManager.retrieve(getCurrentUserOrcid());

// 1. Validate Password
if (form.getPassword() == null || !encryptionManager.hashMatches(form.getPassword(), profile.getEncryptedPassword())) {
    form.setInvalidPassword(true);
    return form;
}

// 2. Validate 2FA
if (!twoFactorAuthenticationManager.validateTwoFactorAuthForm(getCurrentUserOrcid(), form)) {
    return form;
}

// 3. Mark as successful
form.setSuccess(true);
return form;

5. The recovery phone number mode

A third mode sits behind the two above: a code texted to the recovery phone number on the account. It is offered only when the recoveryPhone input is present and its available is true — the feature flag is on, 2FA is active on the account and a number is stored. Without it the panel keeps the ORCID help centre link it has always shown.

This is a library component: it cannot inject an application service, read a feature flag or reach the registry. So the host resolves all of that and hands it over as one plain object, which the component reads live and mutates in place. In the registry that object comes from RecoveryPhoneChallengeService.create().

Accepting one of these codes is not only an authentication. The registry disables 2FA, deletes the number and invalidates the unused backup codes before it answers. The component therefore does not emit submitAttempt when the verify button is pressed in this mode: it calls verify() first, and only once that answers 'passed' does it set used, empty the code fields and emit. The guarded action then runs on the password alone, which works precisely because 2FA has just been turned off. 'invalidCode' leaves the dialog open with an invalid-code error and emits nothing; 'invalidPassword' puts the error on the password instead, exactly as processBackendResponse does for the two ordinary modes, because the Registry never got as far as the code and the one the user typed is still good.

While that request is outstanding the cancel control is disabled and the dialog will not close: a pass has already disabled 2FA, deleted the number and voided the backup codes by the time it answers, and hanging up aborts the request without undoing any of it. For the same reason verify() must do its own bookkeeping on the response rather than in the subscription the challenge holds — that subscription ends when the dialog does. The challenge calls dispose() on the way out, which stops the resend countdown; every other field stays readable, because that is when a host reads used.

After the challenge closes, ask recoveryPhone.used what happened. An action that was itself guarding "disable 2FA" must not run — 2FA is already off. Everything else proceeds exactly as it does after an ordinary pass. 

const recoveryPhone = this._recoveryPhoneChallenge.create();

const dialogRef = this._dialog.open<AuthChallengeComponent>(AuthChallengeComponent, {
  // name the dialog from the challenge's own heading, not a second copy of it
  ariaLabelledBy: AUTH_CHALLENGE_HEADING_ID,
  data: {
    parentForm: this.form,
    actionDescription: '...',
    // which control holds the ACCOUNT password - required here, see below
    passwordControlName: 'oldPassword',
    recoveryPhone
  },
});

dialogRef.componentInstance.submitAttempt
  .pipe(takeUntil(dialogRef.afterClosed()))
  .subscribe(() => {
    if (recoveryPhone.used) {
      // 2FA is already off - do not disable it a second time
      dialogRef.close(true);
      return;
    }
    this.myService.doTheGuardedThing(this.form.value).subscribe(/* ... */);
  });
export interface AuthChallengeRecoveryPhone {
  available: boolean;          // flag on + 2FA on + a number stored
  maskedNumber?: string;       // last four digits only, never the number
  codeSent: boolean;
  resendSeconds: number;       // counts down; 0 means a resend is allowed
  sending: boolean;
  errorCode?: string;          // why the SEND failed, not why a code was rejected
  used: boolean;               // true once a code was accepted, whoever learns first
  sendCode(): void;
  verify(password: string, code: string): Observable<AuthChallengeRecoveryPhoneVerification>;
  dispose(): void;             // called by the challenge when it closes
}

// The Registry checks the password BEFORE the code, so a wrong password comes
// back with no code attempt spent and must not be reported as a wrong code.
type AuthChallengeRecoveryPhoneVerification = 'passed' | 'invalidPassword' | 'invalidCode';
  • parentForm: UntypedFormGroup. (Required) The parent form group containing the controls.
  • actionDescription: string. The contextual text for what the user is doing (e.g. 'to unlink the alternate sign in account').
  • boldText: string. The target of the action to be bolded (e.g. 'Google').
  • trailingText: string. Optional text that appears after the bolded text (e.g. 'to complete your password reset').
  • showPasswordField: boolean. Whether to display the password input field. (default true)
  • showTwoFactorField: boolean. Whether to display the 2FA/Recovery input fields. (default true)
  • passwordControlName: string. The control holding the account password. (default 'password') Required whenever showPasswordField is false and a recoveryPhone is offered: the challenge then reads a control it never displayed, and the default is a guess — in a change-password form password is the new password. Without it the recovery phone option is not offered at all, rather than posting the wrong credential.
  • codeControlName: string. Custom form control name. (default 'twoFactorCode')
  • recoveryControlName: string. Custom form control name. (default 'twoFactorRecoveryCode')
  • recoveryPhone: AuthChallengeRecoveryPhone. Everything needed to offer the third mode, the recovery phone number. Leave it out (or hand over an object whose available is false) and the challenge behaves exactly as it always has. See 5. The recovery phone number mode below.
  • recoveryPhoneControlName: string. Custom form control name for the phone code. (default 'twoFactorRecoveryPhoneCode')
