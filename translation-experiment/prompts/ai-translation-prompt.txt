STEP 1.5 — COMMON PITFALL: SENTENCES SPLIT ACROSS MULTIPLE i18n FRAGMENTS
================================================================================

Some sentences in this app are NOT a single translatable string. They are built
from several separate i18n fragments placed side by side in the template, often
because a clickable link or button sits in the middle of the sentence. Real
example from the register page — and these four keys ARE in your scope, so you
must get them right:

  Template structure (simplified, from step-a.component.html):
    <ng-container i18n="@@register.orcids">Per ORCID's</ng-container>
    <a i18n="@@register.terms">terms of use</a>
    <ng-container i18n="@@register.only">, you may only register for an
      ORCID iD for yourself. Already have an ORCID iD?</ng-container>
    <a i18n="@@register.sign">Sign In</a>

  Rendered in English (reads perfectly, because fragment order matches English
  grammar):
    "Per ORCID's [terms of use], you may only register for an ORCID iD for
    yourself. Already have an ORCID iD? [Sign In]"

  What actually shipped in Spanish (broken — translated fragment-by-fragment
  without checking how they concatenate):
    "DE ORCID [términos de uso de ORCID], solo puede registrar un ORCID iD
    para usted. ¿Ya tiene un ORCID iD? [Iniciar sesión]"
    → Reads as fragmented, ungrammatical Spanish. "DE ORCID" dangles with no
      verb or preposition connecting it to what follows; a native reader has
      to reparse the sentence to understand it.

WHY THIS HAPPENS: each fragment was translated as if it were a complete,
independent sentence, without checking what comes immediately before or after
it in the rendered page. The fragment order and count is FIXED by the HTML
template (you cannot move the link or reorder fragments) — but within each
fragment's text, you have full freedom to phrase things however is needed so
the FULL CONCATENATED SENTENCE reads naturally in the target language.

WHAT TO DO INSTEAD, whenever you see 2+ adjacent i18n fragments (ng-container,
span, a, strong, etc.) that clearly form one sentence together:
  1. Read all the fragments in template order and mentally render the full
     English sentence exactly as a user would see it.
  2. Draft the FULL sentence, correctly and naturally, in the target language —
     as if you were translating one sentence, not four disconnected phrases.
  3. Now split your natural translation back into the same number of pieces,
     in the SAME fixed order as the English template. It's OK — expected,
     even — for an individual fragment's translation to look incomplete or
     grammatically odd in isolation, AS LONG AS the full concatenation reads
     naturally. E.g., a fragment that was "Per ORCID's" in English might need
     to become something like "De acuerdo con los" or similar connective
     phrasing in Spanish so that it flows into the following link text.
  4. Before finalizing, mentally concatenate all fragments in order one more
     time and read the whole sentence in the target language. If it reads
     awkwardly, dangling, or requires the reader to reparse it — revise.

This applies to ANY of your scoped keys that appear as multi-fragment sentences
(check each feature's template carefully for this pattern) as well as any similar
pattern you might notice while exploring nearby out-of-scope strings for context.

STEP 3 — SAVE THE FILES
================================================================================

After producing the JSON, save it to disk using this Node.js script. It is fully
generic — it writes whatever languages/features/keys your JSON contains, so it
needs no changes when the INPUTS change. Fill in MODEL_NAME and paste your JSON:

--- save-translations.js ---

const path = require('path')

const MODEL_NAME = 'YOUR-MODEL-NAME-HERE'  // match what you stated in STEP 0
const BASE = path.resolve('/Users/l.mendoza/code/orcid/orcid-angular/translation-experiment')

const translations = /* PASTE YOUR FULL JSON HERE */

let count = 0
for (const [lang, features] of Object.entries(translations)) {
  for (const [feature, strings] of Object.entries(features)) {
    const dir = path.join(BASE, MODEL_NAME, lang)
    fs.mkdirSync(dir, { recursive: true })
    const outPath = path.join(dir, `${feature}.json`)
    fs.writeFileSync(outPath, JSON.stringify(strings, null, 2) + '\n')
    console.log(`✓ ${MODEL_NAME}/${lang}/${feature}.json`)
    count++
  }
}
console.log(`Done. Wrote ${count} files.`)

--- end ---

Run with:  node save-translations.js

Expected output — one file per (language × feature) under:
  translation-experiment/{MODEL_NAME}/{lang}/{feature-slug}.json
